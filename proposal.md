Problem: A clinical pharmacology team is evaluating multiple-ascending-dose (MAD) trial data to select the optimal Phase 2 dosing regimen for an orally administered therapeutic. The objective is to accurately predict Day 14 steady-state exposure metrics for a newly recruited cohort. Because the compound stimulates its own metabolic clearance through concentration-mediated enzyme turnover, systemic clearance escalates throughout repeated dosing, surges following dose escalation, and gradually returns toward baseline during drug washout. Approximately 70% of participants undergo a mandatory dose-doubling step beginning on Day 8. However, pharmacokinetics for the prospective cohort are monitored only on Days 1, 4, and 7-prior to this titration step-requiring the Day 14 forecast to be an extrapolation across dose and time. Crucially, the informative trough concentrations indicating clearance autoinduction fall predominantly below the assay's lower limit of quantification (LLOQ = 2.50 ng/mL). Omitting below-quantification (BLQ) records, relying on static clearance assumptions, or assuming linear dose proportionality will severely distort Day 14 projections.

Deliverable: A self-contained, offline Python entry point located at /app/submission/predict.py. The execution environment provides historical trial cohorts (including both densely and sparsely sampled arms with titration histories, BLQ status flags, and subject demographics such as weight, age, and sex), a naive prediction script, and an internal interim memo containing flawed pharmacokinetic assumptions. The target script must process these reference files alongside new-cohort data and generate a standard CSV containing one row per subject with fields: subject_id, AUC_ss, Cmax_ss, and Ctrough_ss at Day 14. Operating constraints: zero internet connectivity, a 120-second runtime limit (accommodated up to a 180-second verifier ceiling), 4 CPUs, and 8 GB RAM. The submission must correctly support two optional command-line flags:

--horizon-h H : Forecast evaluation window in hours over the interval [t14, t14 + H), where t14 represents the Day 14 administration time (default 24.0, valid over 0 < H <= 168.0). All three steady-state metrics must be evaluated over this horizon, with trough defined as the plasma concentration at t14 + H.

--estimator {map, population} : Method utilized for individual exposure forecasting (default map: empirical-Bayes maximum a posteriori estimation conditioned on a calibrated population model). In population mode, individual random effects are omitted; projections are derived solely from dosing history and patient covariates, remaining strictly invariant to measured sample concentrations, sampling schedules, censoring indicators, or sample counts. Both modes must complete within runtime limits and output schema-compliant CSVs.

Covariates fallback: Clinical datasets regularly exhibit missing or corrupted covariate annotations. If a subject lacks a covariate entry or provides a missing/non-numeric body weight, the script must substitute a default of 70 kg; invalid or missing age values must resolve to 45 years; and absent or non-standard sex entries (anything other than 'M' or 'F') must default to 'M'. Demographics imputation must occur independently on a per-attribute basis without crashing the pipeline or perturbing calculations for other participants.

Scoring: Submissions are benchmarked against an unseen evaluation cohort of approximately 150 subjects, whose true Day 14 pharmacokinetic profiles are simulated from true latent individual parameters. The discrepancy metric is defined as: raw = 0.5*median(r_AUCss) + 0.3*median(r_Cmaxss) + 0.2*median(r_Ctroughss), where relative error r = |pred - true| / true. The continuous reward is calculated via clip(1 - raw/0.5, 0, 1). The verification suite awards a passing score (binary score = 1) if and only if reward >= 0.50 (corresponding to raw <= 0.25). Automated grading checks also enforce strict CSV formatting, compliance with execution runtime bounds, correct window length scaling under --horizon-h across default and four graded horizons (1.05 h, 6.05 h, 24.05 h, and 47.95 h), strict data-invariance adherence in --estimator population, and robust missing-covariate fallback behavior. Script crashes, schema errors, or timeout violations receive a score of 0.

Why it's hard: The empirical signature of autoinduction is obscured within censored trough measurements gathered under sparse sampling designs. Resolving this challenge requires implementing a non-linear population pharmacokinetic framework with dynamic clearance (e.g., turnover-driven enzyme kinetics where clearance asymptotically climbs under drug exposure), integrated with an exact likelihood treatment for censored observations (such as Beal's M3 method, which models BLQ data points as P(y < LLOQ) rather than dropping or naively imputing them). Furthermore, computing reliable maximum a posteriori (MAP) estimates for sparsely sampled subjects-where most observations are BLQ-necessitates stable empirical-Bayes shrinkage with well-formulated priors. All algorithms, including numerical integration and optimization routines, must be built from scratch and execute in under 120 seconds on 4 CPU cores without commercial NLME tooling. Naive approximations invariably collapse: ignoring censored observations underestimates clearance, and constant-clearance models drastically overproject steady-state concentrations following titration.

Baseline and headroom (measured, local Docker): Empirical benchmarking in the local evaluation environment shows: the naive baseline yields raw = 1.768 (reward = 0.0); multivariable linear regression on dose and covariates without PK dynamics yields raw = 0.514 (reward = 0.0). Conditioned on true simulation parameters, a model lacking induction scores 0.0, typical population estimates alone score 0.487, and an induction formulation uncoupled from concentration achieves 0.638 at 24 h but declines to 0.511 on the 47.95 h extended washout window. The reference solution (M3 censored-likelihood population estimation with turnover autoinduction and MAP empirical-Bayes individualization) reaches raw = 0.109 (reward = 0.783) at 24 h and 0.667 at 47.95 h, successfully passing all 23 grading checks.

Research: Domain literature provides theoretical backing but demands substantial custom engineering. Key foundational concepts include nonlinear mixed-effects modeling (FOCE/SAEM approximations), Beal (2001) methodologies for handling bioanalytical censoring (M1 to M7 frameworks), and published enzyme autoinduction turnover kinetics (e.g., clearance mechanisms reported for carbamazepine and rifampicin). The agent must formulate a parsimonious, identifiable structural PK model suitable for sparse profiles, code the censored likelihood and numerical optimization routines from scratch, handle all-BLQ participant histories gracefully, establish data-driven priors from the historical training cohort, ensure numerical stability across both estimation modes, and compute arbitrary-horizon exposure integrals (AUC_ss, Cmax_ss, Ctrough_ss) efficiently.

Resources and privacy: Runs on 4 CPUs, 8 GB RAM, and standard scientific Python packages (numpy, scipy, pandas) without requiring GPU acceleration. Historical training cohorts are simulated using an oral one-compartment model featuring absorption delay, concentration-regulated enzyme turnover, subject-level titration schedules, proportional residual assay variance, and LLOQ truncation. The hidden evaluation cohort and underlying ground-truth parameters are generated using an independent seed (8675309) and isolated within the verification container, entirely inaccessible to the agent during runtime. Tests execute /app/submission/predict.py against the hidden inputs to score output CSVs, strictly preserving evaluation integrity.
