Problem: A clinical pharmacology group must choose the phase-2 dose of an oral drug from a once-daily multiple-ascending-dose (MAD) study. It needs day-14 steady-state exposure forecasts for a new cohort. The drug auto-induces its own clearance, so clearance rises over the dosing period. The earliest evidence of this induction is in sparse trough samples, many of which are below the limit of quantification (BLQ). Dropping BLQ samples, substituting LLOQ/2, or assuming time-invariant clearance biases every day-14 exposure forecast.

Deliverable: An offline Python script at /app/submission/predict.py. The agent starts with a container holding the historical study data (dosing records, PK samples with a BLQ flag, subject covariates such as weight, age, sex, dose level) and a data-schema README. The script ingests these files plus a new-cohort file and writes a CSV with one row per subject: subject_id, AUC_ss, Cmax_ss, Ctrough_ss (day-14 steady state). Constraints: no network access, at most 120 seconds of wall-clock time (up to 180s verifier host ceiling), 4 CPUs, 8 GB RAM. Two optional flags must be implemented correctly:

--horizon-h H : forecast window length in hours over [t14, t14+H), where t14 is the day-14 dose time (default 24.0, with 0 < H <= 168.0). All three quantities are recomputed over that window (trough is the concentration at t14+H).

--estimator {map, population} : how each subject's forecast is derived (default map: empirical-Bayes individual estimates given a fitted population model). With population, individual random effects are not fitted; each subject's forecast depends strictly on its dosing and covariates, remaining 100% invariant to measured sample values, timing, censor flags, and row counts. Each option must run within the time limit and produce a valid CSV.

Covariates fallback: Real cohorts may have incomplete covariates. When a subject has no covariates row or its body weight is blank/non-numeric, the script must default to 70 kg for that field; when sex is blank or not 'M'/'F', it must default to 'M'. Unusable fields fall back per field without aborting the run or altering other subjects.

Scoring: Evaluated on a hidden cohort of about 150 unseen subjects, whose true day-14 values are computed from simulated true individual parameters. The raw metric is raw = 0.5*median(r_AUCss) + 0.3*median(r_Cmaxss) + 0.2*median(r_Ctroughss), where r = |pred - true| / true. Reward is clip(1 - raw/0.5, 0, 1). The task passes (scores 1) only when reward >= 0.50, i.e. raw <= 0.25. Hidden tests also check that the CSV schema is correct, the runtime limit holds, --horizon-h changes the forecast window length as documented (e.g. an earlier horizon gives less induced clearance and higher exposure), both --estimator options run and pass accuracy, and covariate fallbacks function properly. A failed run, malformed CSV, or timeout scores 0.

Why it's hard: The induction signal lives in censored troughs during sparse sampling. A solution needs a population PK model with time-varying clearance (for example CL(t) rising toward an asymptote via an enzyme-turnover or exponential-onset term), plus a censored-data likelihood (such as the M3 method, which treats a BLQ record as P(y < LLOQ) instead of discarding it). It also needs stable empirical-Bayes estimates for subjects with only a few samples, mostly BLQ, which means sensible priors and shrinkage. All of this must run inside 120 seconds on 4 CPUs without a dedicated NLME package, so the optimizer and the ODE or analytic solution must be efficient. Common shortcuts fail: dropping BLQ samples or using LLOQ/2 biases clearance, and a constant-clearance model overpredicts day-14 exposure.

Baseline and headroom: a naive baseline (empirical non-compartmental summary, BLQ rows dropped, no PK model) gives raw = 0.621 (reward = 0.0), which fails. A well-specified population model with M3 censoring and an induction term reaches raw = 0.136 (reward = 0.728), leaving substantial headroom between the baseline and the pass threshold.

Research: Public work helps but leaves substantial engineering. Useful references: nonlinear mixed-effects estimation (FOCE and SAEM), Beal (2001) on handling BLQ data (M1 to M7 methods), and published autoinduction PK models (turnover-based CL models for drugs such as carbamazepine and rifampicin). Still to be done by the agent: choosing an identifiable structural model for sparse data, implementing the censored likelihood and the optimizer from scratch, handling subjects with all samples BLQ, setting priors from the historical cohort, making both estimators fast and numerically stable, and computing steady-state AUC, Cmax and Ctrough at an arbitrary horizon.

Resources and privacy: Needs 4 CPUs, 8 GB RAM, and standard scientific Python (numpy, scipy, pandas) with no GPU. The visible training data is simulated from a fixed PopPK model with autoinduction, with added residual error and BLQ censoring. The hidden cohort and its ground-truth exposures are generated with a separate seed (8675309) and kept only in the grading step, never in the agent's container. Tests run predict.py on the hidden inputs and score the CSV, so authoritative scores stay inaccessible to the agent.
