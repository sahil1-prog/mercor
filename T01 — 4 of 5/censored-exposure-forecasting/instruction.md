A clinical pharmacology team is selecting the Phase-2 target dose for an oral drug evaluated in a once-daily multiple-ascending-dose (MAD) trial with an in-study dose titration step, and requires Day 14 steady-state exposure forecasts for an incoming cohort. Your primary working directory is `/app`.

Historical trial data is provided in `/app/data` (a rich cohort in `/app/data/rich` with full concentration profiles across Day 1 and Day 14, and a sparse cohort in `/app/data/sparse` matching the new cohort's sampling schedule), a simple baseline predictor at `/app/baseline/predict.py`, and an interim team memo at `/app/analysis/prior_memo.md`. Review these resources as needed. The environment runs completely offline with 4 CPUs and 8 GB of RAM.

Deliver `/app/submission/predict.py`. It will be evaluated on an unseen cohort of roughly 150 subjects following the sparse sampling schedule of `/app/data/sparse` — a few samples collected on Days 1, 4, and 7 without subsequent draws — generated from the same population distribution and dosing regimen as the visible cohorts. Input files adhere to the schemas below. The evaluation harness runs:

`python3 /app/submission/predict.py --input-dir DIR --output OUT.csv [--horizon-h H] [--estimator E]`

and grades `OUT.csv`. During grading, only `DIR` and files included in `/app/submission` are present — `/app/data`, `/app/baseline`, and `/app/analysis` will be absent, so any population model fit on historical data must be saved as an artifact inside `/app/submission`. Your program may use standard Python libraries and preinstalled packages. It must write `OUT.csv` and nothing else into the output directory, and must leave files in the input directory and `/app/submission` unmodified (Python bytecode caches are exempt); temporary files should be written under `/tmp`. The script must finish within a 120-second wall-clock runtime budget (with a 60-second host load grace, giving an absolute 180-second ceiling) from launch to exit, and repeated runs on identical inputs must yield identical predictions.

The optional argument `--horizon-h H` sets the evaluation window length in hours, defining endpoints across `[t14, t14+H)` rather than standard `[t14, t14+24)`; all three exposure metrics are recalculated over this window (with trough defined as the concentration at `t14+H`). Omission selects default `H = 24.0`, which must match standard 24-hour calculations exactly. `H` must be finite with `0 < H <= 168.0`; invalid values (zero, negative, non-numeric, or greater than 168) must exit non-zero without writing output. Runs using `--horizon-h H` are scored against ground-truth exposures for `[t14, t14+H)`. Evaluation windows that do not align with integer integration steps are tested, requiring exact window boundary handling rather than grid snapping.

The optional argument `--estimator E` specifies the estimation approach, accepting either `map` or `population`. These values must match the exact strings: inputs like `MAP`, ` map `, or `Population` must exit non-zero with no output. The default `map` option runs empirical-Bayes individualization. In contrast, running `--estimator population` must NOT estimate individual random effects: forecasts must depend solely on dosing records and patient covariates, remaining completely invariant to sample concentrations, sampling schedules, censoring flags, observation counts, or `subject_id`. It must still respond to dose level and body weight. The `population` setting is tested for adherence to these invariance rules rather than prediction accuracy.

Each input directory contains four CSV files with header rows:

- `subjects.csv`: `subject_id,dose_mg` — `dose_mg` represents the starting dose.
- `doses.csv`: `subject_id,dose_time_h,dose_mg,administered` — one record per planned dose in scheduled sequence. `dose_mg` indicates administered amount: patients may step up to higher doses mid-study. On `administered=1` rows, `dose_time_h` is the actual administration time in hours relative to first dose; on `administered=0` rows, it marks planned time and contributes no active drug.
- `samples.csv`: `subject_id,sample_time_h,concentration_ng_ml,censored` — plasma concentration observations. `censored=1` indicates values below the assay limit of quantification (LLOQ = 2.50 ng/mL) where `concentration_ng_ml` is a placeholder; `censored=0` rows are valid bioanalytical measurements.
- `covariates.csv`: `subject_id,body_weight_kg,age_years,sex`.

Let `t14` be the maximum `dose_time_h` across all rows in `doses.csv`, regardless of row index or `administered` value: this marks the Day 14 dose administration time. Target values describe the `[t14, t14+24)` hour interval: `auc_ss` is the area under the concentration-time curve (ng*h/mL), `cmax_ss` the maximum concentration (ng/mL), and `ctrough_ss` the concentration at `t14+24` (ng/mL). Records in input files may appear in arbitrary order.

Write `OUT.csv` containing columns `subject_id,auc_ss,cmax_ss,ctrough_ss`: exactly one row per subject in `subjects.csv`, identical `subject_id` strings, with all metrics reported as finite positive numbers. Extraneous columns are ignored. Clinical data often has missing entries, so data issues must not crash the run: if a subject has no record in `covariates.csv` or has a blank/invalid `body_weight_kg`, use 70 kg; if `age_years` is missing or invalid, use 45 years; and if `sex` is blank or not `M`/`F`, use `M`. Apply fallbacks independently per field — valid fields must still be respected — output a full row for that subject, and leave forecasts for all other subjects unaffected.

Scoring. For each subject and exposure metric, let `r = |predicted - true| / true`. The composite metric is

`raw = 0.5*median(r_AUCss) + 0.3*median(r_Cmaxss) + 0.2*median(r_Ctroughss)`

and your reward is `clip(1 - raw / 0.5, 0, 1)`. The submission passes — receiving a score of 1 — when this reward is at least 0.50 (i.e. `raw <= 0.25`); otherwise it scores 0. Missing files, malformed formatting, incomplete outputs, non-finite values, or non-deterministic behavior score 0.
