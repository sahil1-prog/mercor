Your primary working directory is `/app`.

Review these files as needed. The runtime environment operates fully offline with 4 CPUs and 8 GB of RAM.

Deliver `/app/submission/predict.py`. The model will be graded on a new, unseen evaluation cohort of approximately 150 participants sharing the sparse collection schedule of `/app/data/sparse` — limited plasma observations collected on Days 1, 4, and 7 without subsequent sampling — generated from the identical underlying population distribution and dosing design, ensuring calibrated parameters from visible data directly generalize to it. Input files follow the schemas specified below. The evaluation harness invokes:

`python3 /app/submission/predict.py --input-dir DIR --output OUT.csv [--horizon-h H] [--estimator E]`

and assesses the generated `OUT.csv`. The script must write `OUT.csv` and no other files into the target output directory, and must leave files in the input directory and within `/app/submission` completely unaltered (standard Python bytecode caches are exempt); intermediate or temporary data should be created under `/tmp`. Execution must terminate within a 120-second wall-clock budget (with an additional 60-second host system margin, providing a maximum upper ceiling of 180 seconds) from launch to process exit, and repeated executions on identical input cohorts must return identical numeric outputs.

The optional argument `--horizon-h H` configures the evaluation window duration in hours, defining endpoints over `[t14, t14+H)` rather than standard `[t14, t14+24)`; all three exposure metrics are recalculated across this specified window (with trough defined as the plasma concentration at `t14+H`). Omitting this flag invokes default `H = 24.0`, which must exactly match standard 24-hour calculations. `H` must be a finite numerical value satisfying `0 < H <= 168.0`; any other argument (zero, negative values, non-numeric strings, or values exceeding 168) must terminate with a non-zero exit status without writing an output file. Evaluations under `--horizon-h H` are graded using the identical scoring function and passing threshold against the ground truth of `[t14, t14+H)`. Evaluation windows not aligning with whole integration steps are tested, meaning arbitrary window boundaries must be integrated precisely rather than snapped to pre-set grids.

The optional argument `--estimator E` designates how individual subject predictions are computed, accepting either `map` or `population`. These values must match the exact lowercase strings: tokens such as `MAP`, ` map `, or `Population` are rejected and must cause immediate non-zero process termination without emitting output. The default `map` option executes full empirical-Bayes individualization. In contrast, running `--estimator population` must NOT compute individual-level random effects: subject forecasts must depend strictly on dosing schedules and demographic covariates, remaining wholly independent of observed sample values — two patients having identical dosing rows and baseline covariates but different concentration samples must receive identical exposure values, and forecasts must not vary based on sample concentrations, timing, censoring flags, observation counts, or `subject_id`. It must remain responsive to regimen and demographic differences — subjects differing solely in dose level or weight must yield distinct exposures. The `population` setting is tested specifically for adherence to these invariance constraints, rather than for numerical estimation accuracy.

Each input directory contains four headered CSV files:

- `subjects.csv`: `subject_id,dose_mg` — `dose_mg` denotes the participant's starting dose amount.
- `doses.csv`: `subject_id,dose_time_h,dose_mg,administered` — one record per planned dose in scheduled sequence. `dose_mg` indicates administered mass: subjects may step up to higher dosage tiers mid-study, so amounts vary across rows. For `administered=1` entries, `dose_time_h` marks the true administration hour relative to the initial planned dose (accounting for dose delays); for `administered=0` entries, it denotes the scheduled time but imparts no drug.
- `samples.csv`: `subject_id,sample_time_h,concentration_ng_ml,censored` — plasma bioanalytical records. `censored=1` denotes measurements below the assay limit of quantification (LLOQ = 2.50 ng/mL) where `concentration_ng_ml` represents an uninformative numerical placeholder; `censored=0` records correspond to true quantified concentrations.
- `covariates.csv`: `subject_id,body_weight_kg,age_years,sex`.

Define `t14` as the maximum `dose_time_h` across all records in `doses.csv`, irrespective of row position or `administered` indicator status: this marks the Day 14 dose administration time. Target quantities reflect the `[t14, t14+24)` hour interval: `auc_ss` represents the area under the concentration-time curve (ng*h/mL), `cmax_ss` the maximum observed concentration within the interval (ng/mL), and `ctrough_ss` the plasma concentration at `t14+24` (ng/mL). Records in the tables are not guaranteed to appear in sorted temporal order.

Write `OUT.csv` with exactly the columns `subject_id,auc_ss,cmax_ss,ctrough_ss`: one row per subject in `subjects.csv`, same `subject_id` strings, every value a finite positive number. Extra columns are ignored. Real cohorts are incomplete, so do not abort the whole run on a bad subject: when a subject has no `covariates.csv` row, or its `body_weight_kg` is blank or not a usable positive number, use 70 kg for that field; when its `age_years` is blank or not a usable positive number, use 45 years; when its `sex` is blank or not `M`/`F`, use `M`. Fall back per field - usable fields are still honoured beside an unusable one - still emit a complete row for that subject, and leave every other subject's prediction unchanged.

Scoring. For each subject and quantity let `r = |predicted - true| / true`. The raw metric is

`raw = 0.5*median(r_AUCss) + 0.3*median(r_Cmaxss) + 0.2*median(r_Ctroughss)`

and your reward is `clip(1 - raw / 0.5, 0, 1)`. Your submission passes - and is scored 1 - when that reward is at least 0.50, i.e. when `raw <= 0.25`; otherwise it is scored 0. A missing, malformed, incomplete, non-finite, or non-reproducible submission scores 0.
